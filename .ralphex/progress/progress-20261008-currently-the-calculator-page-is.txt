[2026-10-08] Task 1 (Diagnose the broken Calculator page) — diagnosis complete.

Reproduced the failure by booting the plugin under Orchestra Testbench and
rendering the Calculator page through the controller (no HTTP/auth needed;
the failure is in view compilation, before any SeAT layout logic runs).

Exact error (rendering the Calculator with a seeded recipe, bp=681):
  Illuminate\View\ViewException: syntax error, unexpected token "endif"
  (View: src/resources/views/calculator/index.blade.php)
The compiled view contains an orphan `<?php endif; ?>` with no matching `if`.

Location of the page:
  Route:      src/Http/routes.php  GET /industry-manager/calculator
              (name industry-manager.calculator, middleware can:industry-manager.calculate)
  Controller: src/Http/Controllers/IndustryManagerController.php::calculator()
  Views:      src/resources/views/calculator/index.blade.php
              src/resources/views/calculator/_assignment.blade.php
              src/resources/views/calculator/_tree_node.blade.php

Root cause: on line 83 of calculator/index.blade.php the structure <option>
has two Blade directives written back to back with no separator:
  ...@if($st['scope'] === 'alliance') · alliance @endif@if(!($st['contents_known'] ?? true)) · contents unknown @endif
Blade's statement regex anchors directives with `\B@`; after `@endif` the next
character is `f` (a word char) followed by `@`, which is a word boundary, so the
second `@if` is not recognised and survives as literal text while its trailing
`@endif` still compiles — an orphan `endif` and a PHP syntax error. The defect was
introduced when the `@if(... contents_known ...)` clause was appended directly
after the existing `@endif` (commits 8c3581b, reused by 0cb09d5).

Smallest change that restores rendering: put whitespace between the two
directives, i.e. `@endif @if(...)`. Verified locally by temporarily inserting the
space: the same render test passed (assertion that "Test Blueprint" appears).
That edit was reverted; applying it is Task 2's job.

Stale reference check: NOT a stale release reference. The route, controller and
all three Blade views exist; `contents_known` is produced by StructureService::
forUser() and consumed consistently. No missing view, renamed class or changed
config key is involved.

Verification: full suite `composer test` -> OK, 148 tests, 613 assertions, 1 deprecation, 3 skipped.
